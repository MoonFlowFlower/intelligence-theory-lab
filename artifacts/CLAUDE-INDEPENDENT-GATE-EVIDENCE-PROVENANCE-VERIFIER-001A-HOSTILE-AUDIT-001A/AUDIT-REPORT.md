## 8. Strongest objection

**The verifier cannot catch the exact class that produced the Route C false positive: metric degeneracy and omitted / mis-declared strongest fair baseline.** Two independent probes confirm this concretely, both returning `provenance_wellformed_only`:

- **P2** — candidate 0.99 vs declared strongest-fair 0.05, delta 0.94, equivalence_band 0.01. No margin-vs-band adjudication is performed.
- **P4** — a second, invoked baseline is present, yet a weaker baseline is still declared `strongest_fair_baseline_id`. No cross-baseline maximum check is performed.

This is the decisive framing of the tool: it verifies that provenance evidence has the right *shape and internal cross-references*, not that the evidence is *valid* or that the baseline panel is *adequate*. It is a prefilter, not an admission gate (Strongest Objection #6 and #7 are upheld; #3 is upheld and is the headline caveat). It must be paired with — and never substituted for — the separate `BASELINE-IMMUNITY-ADMISSION-STANDARD`, which the verifier does not implement.

Secondary objections, all non-blocking: replay/source-pin/leakage/consumption are declaration-shape checks on self-reported fields (verifier does not recompute or re-hash); committed tests omit four present-but-invalid sub-paths the code nonetheless handles; fixtures use constant fabricated hashes (fine for shape testing, never exercises a real hash mismatch); dead branch at `verifier.py:248-249`; `P3` internal-blocked-but-shape-valid returns wellformed (benign direction).

## 9. Recommendation

Accept the verifier as a local provenance-shape **prefilter / admission-support tool**. Wire nothing into runtime or admission. Treat `provenance_wellformed_only` strictly as "this bundle is provenance-shape well-formed and internally cross-referenced," never as Gate pass, mechanism validity, baseline-immunity, or admission. The most valuable hardening would be a one-card, scope-bounded test addition for the four missing sub-paths — optional, non-blocking, no scope expansion.
