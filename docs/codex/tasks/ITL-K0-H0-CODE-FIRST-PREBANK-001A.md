## 3. Bounded audit

### Hypothesis

A typed code-first registry and one reusable primary H0 resolver can make the
admission semantics total, component-local, permutation-invariant, and
mutation-sensitive while an independently implemented oracle agrees on frozen
scenarios and cheap schema/blob/self-check baselines fail to match the
candidate's discrimination.

### Strongest baseline and invalidity risk

- Strongest baseline explanation: the package is only a more elaborate schema
  checker whose positive cases are encoded in its fixtures. Exact blob
  equality, permissive parsing, the same resolver called twice, or a synthetic
  witness may reproduce a green report without independent H0 semantics.
- Strongest reason the task may be invalid: the typed registry and validation
  catalog may still be self-authored and self-confirming. Agreement between
  candidate and oracle is not discriminative if they share decision branches,
  if normative mutations do not reach execution, or if positive witnesses are
  synthesized from the same resolver.
- Framing falsifier: any normative leaf mutation survives; any
  semantics-preserving transformation is rejected; a raw contrast permutation
  changes a terminal result; deletion or renaming of a required arm is
  accepted; primary resolver and independent oracle disagree; a frozen
  scenario/mutation/permutation id is unused; or the route validator must
  duplicate H0 domain semantics.
- Evidence still insufficient: even a fully green prebank validates only this
  code-first contract instrument at the prebank boundary. It does not establish
  instrument validity under formal data, H0 pass, mechanism evidence, learning,
  replay contribution, memory causality, transfer, initiative, or mainline
  effect.
- Test classification: this tests engineering/evidence hygiene for a mechanism
  instrument. It does not test behavioral resemblance and does not execute a
  mechanism episode.

### Anti-hardcoding and evidence-integrity audit

- Hard-coding: forbidden; no static verdict dictionary, placeholder arm,
  string formula interpreter, threshold tuning, or fixture-only alternate
  resolver.
- Local optimum: a green schema/parser result is not sufficient; discrimination
  against valid transformations and invalid normative mutations is required.
- Audit-Zeno: no new JSON overlay and no post-run repair are allowed.
- Evidence leakage: the independent oracle may share typed schema/enums but not
  reducer decision branches/helpers; baselines and ablations are callable
  independent paths.
- Weak baseline: exact-blob, permissive parse, same-resolver-twice, and synthetic
  witness baselines are mandatory and cannot earn success by rejecting every
  input.
- Schema split/second path: route governance checks pins/authority/paths only;
  H0 domain semantics live only in the final package resolver/registry path.
- Replay weakness: semantic replay must recompute from serialized registry/spec
  plus observation; stored verdict/hash comparison alone is forbidden.
- Claim inflation: `CODE_FIRST_PREBANK_VALIDATED` is not H0 pass, instrument
  validity, or mechanism evidence.

## 4. Collision record

### A. Add another JSON overlay - rejected

- Evidence produced: another pinned schema delta and validator report.
- Strongest cheap baseline that can match: exact-literal or exact-blob equality.
- Leakage/hard-coding risk: high; new literals can be wired directly into the
  existing validator while normative fields remain unused.
- Smallest falsifying test: mutate a normative field not read by the validator;
  acceptance demonstrates non-enforcement.
- Expected failure mode: audit-Zeno with more governance surface and no stronger
  semantic evidence.

### B. Continue the H0 resolver inside the route validator - rejected

- Evidence produced: a green route-governance report and larger route tests.
- Strongest cheap baseline that can match: route validator calls its own
  resolver twice or exact-matches the banked object.
- Leakage/hard-coding risk: critical; route governance becomes a second H0
  implementation and self-validates its own domain semantics.
- Smallest falsifying test: package and route-validator results diverge after a
  normative mutation or permutation.
- Expected failure mode: two logic paths, ambiguous authority, and false
  confidence from self-consistency.

### C. Temporary preflight package copied later into formal H0 - rejected

- Evidence produced: isolated preflight tests and generated artifacts.
- Strongest cheap baseline that can match: a temporary fixture-specific
  implementation whose assumptions disappear during the copy.
- Leakage/hard-coding risk: high; copy drift creates a second implementation
  path and invalidates source/freeze pins.
- Smallest falsifying test: copied formal resolver differs by blob or behavior
  from the preflight resolver.
- Expected failure mode: prebank evidence does not apply to the later package.

### D. Implement code-first prebank in the final H0 package path - selected

- Evidence produced: typed canonical registry, actual per-arm atomic specs,
  component-local reducers, independently implemented oracle, frozen
  mutation/metamorphic/permutation catalogs, callable baselines/ablations,
  semantic recomputation, path-authority evidence, and immutable source/freeze
  pins.
- Strongest cheap baseline that can match: a fixture-derived validator plus
  exact-object recognition; the mandatory baseline and mutation/metamorphic
  contrast is designed to expose this.
- Leakage/hard-coding risk: bounded but not eliminated. It is controlled by
  independent branches, automatic normative-leaf enumeration, valid
  transformations, positive and negating scenarios, and post-freeze one-run
  discipline.
- Smallest falsifying test: any item in Section 3's framing falsifier.
- Expected failure mode: a frozen probe reveals self-reference, missing
  semantics, order dependence, or unused normative data. That negative result
  is banked and closes this admission-science branch.

Selection rationale: D is the only approach that avoids a new overlay, avoids
route-validator domain semantics, and preserves one reusable resolver/registry
path for future formal H0/H1 use. This remains a formal engineering approach,
not evidence that H0 or a mechanism is valid.

## 5. Registry, atomic-spec, and reducer contract

1. The typed canonical registry contains exactly five evidence components:
   `V_model`, `V_online`, `V_replay`, `V_memory`, and `V_transfer`.
2. Each component has separate causal, control, rival, and integrity panels.
3. `V_special` is only a derived claim-admissibility predicate and never an
   evidence axis.
4. Actual `AtomicContrastSpec` records are generated from the typed registry.
   Every record contains `atomic_contrast_id`, component, panel, arm, role,
   full/intervention/reference arms, family/protocol, estimand, expected sign,
   success/failure/ambiguous signatures, power spec, seed block, blast radius,
   and resolver id. All references resolve; no generic family, candidate
   placeholder, or aggregate panel id substitutes for a required arm.
5. Atomic-spec count is computed from the registry rather than fixed to 90.
6. Component resolution first scans all mandatory causal dependencies for
   missing, invalid, or underpowered inputs. Invalid or underpowered yields
   `INVALID_INSTRUMENT`; otherwise any powered `NO_CONTRIBUTION`/`WRONG_SIGN`
   yields `ABSENT`; otherwise all mandatory expected-sign contributions yield
   `PRESENT_BOUNDED`; not-started inputs yield `NOT_TESTED`.
7. No first-hit early return may make the result order-dependent.
8. Control/rival reduction is per component. Powered comparator superiority is
   `DOMINATED`; powered parity/ceiling is `EQUIVALENT`/`SATURATED`; only all
   required, run, powered, candidate-superior comparators yield `SEPARATED`;
   missing/underpowered inputs yield `NOT_RUN`/`INCONCLUSIVE`. A global scalar
   may not erase component differences.

## 6. Independent oracle and frozen validation contract

- The reference oracle may share typed schema and enums with the primary
  implementation but may not call or share reducer branches/helpers.
- The oracle is evidence-validation-only; H1 must never call it.
- Frozen scenarios include an admissible positive case and every negating
  condition.
- `normative_field_manifest.json` enumerates every normative leaf. Each leaf
  has at least one mutation that actually changes an input and calls the real
  validator. Metadata exclusions are finite, explicit, and justified.
- Normative mutation kill rate must equal 1.0.
- Semantics-preserving transformations include JSON key order, set-like arm
  order, metadata-only fields, and canonical-equivalent serialization. Valid
  transformation accept rate must equal 1.0.
- Causal panels with at most six arms execute all permutations. Larger
  comparator panels use frozen reversed, rotated, single-change, and
  fixed-seed permutation-bank cases. Every frozen permutation id is consumed.
- Permutation validation recomputes results and may not compare stored hashes
  alone.
