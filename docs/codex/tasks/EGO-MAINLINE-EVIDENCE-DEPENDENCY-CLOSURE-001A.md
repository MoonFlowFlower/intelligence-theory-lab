`evidence_dependency_closure`, compute the evidence dependency state required

conflicting dependencies, known blockers, failed-test implications, and the
safest next bounded task.

## Current Stage

## Hypothesis

A correct dependency closure prevents premature advancement by requiring
explicit upstream evidence continuity, clean or classified test-suite status,
anchor integrity, artifact provenance continuity, replay/leakage/provenance
gates, and non-authorization preservation before any stronger downstream route
is allowed.

## Strongest Baseline Explanation

The strongest unsafe baseline is targeted-test advancement: if the routing test
passes, a naive closure may ignore suite-level blockers and over-route toward a
future downstream boundary.

## Strongest Reason This Task May Be Invalid

This task can only classify dependency state. It cannot repair test failures,
add mechanism evidence, validate theory, prove architecture correctness, or
authorize downstream runtime work.

## Falsification Condition

The current framing is falsified if required routing/admission anchors do not
resolve exactly, routing artifacts are missing, known failures are ignored, a
full-suite limitation is hidden, baselines or ablations are skipped, leakage
