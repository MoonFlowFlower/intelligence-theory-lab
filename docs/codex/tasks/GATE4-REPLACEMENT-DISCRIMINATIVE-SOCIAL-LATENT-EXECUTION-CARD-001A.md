## Problem Definition

Draft a bounded future execution-card for a replacement Gate4 discriminative
social-latent task. The future experiment must be able to fail for the right
reasons.

The future target is not:

> Make Gate4 pass.

The future target is:

> Require a candidate to beat independent lookup, retrieval, table, traversal,
> FSM, transition, and graph-cache baselines under split families that break
> stable ID keys, require active information acquisition, require posterior or
> state update from feedback, and verify replay recomputation from serialized
> state plus observation.

## Hypothesis

A future replacement Gate4 can become more discriminative than 001C only if it
forces generalization and intervention response across latent social/preference
structure while blocking stable stream-key lookup, static retrieval, transition
tables, and replay-by-hash.

This is a contract hypothesis, not an evidence result.

## Baseline

The strongest baseline family to beat is the prior stream-keyed count-table
challenger over `(seed, context_id, partner_id)`.

The future baseline suite must also include independent callable:

- stream-keyed count table
- normalized retrieval
- nearest-neighbor lookup
- context-partner table
- `graph_lookup`
- `transition_table`
- `successor_map`
- `count_table`
- `fsm_planner`
- `episodic_traversal`
- no-state ablation
- no-feedback ablation
- no-action ablation
- oracle-label positive control only

Any tie between the candidate and the strongest non-oracle baseline blocks
positive evidence.

## Ablation

Future ablations must be real reruns under interventions, not post-hoc score
edits. Required future ablations include:

- no-state
- no-feedback
- no-action
- no-active-query
- shuffled-feedback
- counterfactual-transition

No-active-query and shuffled-feedback ablations must drop at least `0.20` on
active query-required episodes. Counterfactual-transition ablation must drop at
least `0.15` on counterfactual intervention and active query-required episodes.

## Trace / Replay Requirement

Future replay must recompute behavior from:

- `serialized_state`
- observation
- action policy path
- update path
- feedback history

Future replay must verify both action recomputation and state-update
recomputation. Stored-action replay and action-hash-only replay are invalid.

## Metric Threshold Gate

Future metric pass/fail thresholds:

1. Ties block. Any tie between candidate and strongest non-oracle baseline
   blocks positive evidence.
2. Aggregate margin: `aggregate_delta >= 0.15`.
3. Confidence rule:
   `lower_bound_95pct(candidate_minus_strongest_baseline) > 0.05`. If
   confidence intervals are not used, the future task must replace them with a
   repeated-seed stability rule and justify the replacement.
4. Split-level margin: `split_delta >= 0.10` on every critical split.
5. No aggregate rescue. Aggregate success cannot override failure on any
   critical split.
6. Repeated seed stability: at least 5 independent seeds; at least 4 of 5
   seeds must satisfy aggregate margin; no seed may show candidate below the
   strongest non-oracle baseline on active query-required episodes; no critical
   split may fail in the seed-aggregated result.
7. Oracle-label positive control is a positive control only, not an ordinary
   baseline to beat. If it fails to outperform ordinary baselines, the
   task/harness is invalid.
8. Future failure semantics must distinguish candidate failure, baseline parity
   failure, split failure, active-query causal failure, leakage scan failure,
   replay recomputation failure, provenance failure, and harness invalidity.

## Mandatory Split Families

The future execution must include:

- seen partner / unseen context
- unseen partner / seen context
- unseen partner / unseen context
- unseen preference transition
- counterfactual intervention
- active query-required episodes
- heldout episodes with remapped IDs

Failure on any critical split blocks positive evidence.

## Budget Parity Gate

Candidate and baselines must share the same legal interface unless a difference
is explicitly justified and recorded. Required parity dimensions:

- same observation interface
- same action interface
- same reward/feedback interface
- same history interface
- same legal input access
- comparable episode count
- comparable training/update exposure
- comparable query budget
- comparable update budget
- comparable history window
- comparable state capacity or explicit capacity sweep
- no candidate-only hidden information
- no baseline-only handicap
- no baseline denial of legal feedback available to candidate
- no candidate access to latent labels unless the same labels are available to
  baselines
- no metric computed from hidden labels unavailable at decision time

If candidate has learned state capacity, future baselines must receive either a
matched capacity budget or an explicit capacity sweep.

## Active-Query Causal Gate

Future active-query evidence must show:

- uncertainty before query/action
- query/action chosen by candidate policy path
- query changes received observation, feedback, or available evidence
- feedback updates serialized candidate state through candidate update path
- updated state changes at least one later action or policy distribution
  relative to no-query or shuffled-feedback counterfactual
- no-active-query ablation drop at least `0.20`
- shuffled-feedback ablation drop at least `0.20`
- counterfactual-transition ablation drop at least `0.15`
- replay recomputes action and state update

Future traces must include pre-query observation, uncertainty representation or
legal uncertainty proxy, selected query/action, received feedback, serialized
state before and after update, later action under updated state, later action
under no-query counterfactual, later action under shuffled-feedback
counterfactual, producer function, invocation path, run id,
seed/context/partner/episode IDs, and code path hash.

## Baseline Independence Gate

Future tests must prove baseline invocation is real:

- each baseline callable is invoked at least once per required split
- disabling any mandatory baseline causes future harness failure
- strongest baseline is selected by computed metric, not static declaration
- oracle-label positive control is invoked separately from non-oracle baselines
- baseline outputs are generated from legal input artifacts, not literals
- baseline code path hash is recorded
- baseline scores cannot be manually inserted into result JSON

Baselines may share common IO schemas and metric utilities. They must not share
candidate policy code, candidate update logic, candidate latent inference code,
or candidate state transition code.

## Computed-Evidence Provenance Gate

Every future score must be computed by callable paths. No score may be accepted
from static JSON, hardcoded constants, self-reported pass/fail files, or tests
that merely assert pass.

Every future score must record:

- `producer_function`
- `input_artifacts`
- `run_id`
- `seed_ids`
- `context_ids`
- `partner_ids`
- `episode_ids`
- `split_id`
- `aggregation_rule`
- `code_path_hash`
- `baseline_invocation_path`
- `ablation_invocation_path`
- `leakage_scanner_path`
- `replay_recompute_path`

Missing provenance blocks positive evidence. Any unused frozen seed, train
context, heldout context, counterfactual pair, or remapped-ID episode blocks
positive evidence.

## Leakage Positive-Control Contract

control scans may supplement but may not replace real-bundle scans.
