# COMPUTED-EVIDENCE-PROVENANCE-CONTRACT-001A

## 1. Task Identity

```text
task_id = COMPUTED-EVIDENCE-PROVENANCE-CONTRACT-001A
layer = bounded repo-standard contract only
execution_type = documentation-and-validation-artifact standard
verdict = computed_evidence_provenance_contract_001a_created
claim_ceiling = bounded repo-standard contract evidence only
```

This is a forward-facing repository standard for future executable evidence
tasks. It is not a new experiment, rerun, result audit, EGO-mainline readiness
audit, bridge runtime task, or amendment that can make
`POST-BRIDGE-ADMISSION-EXECUTABLE-001B` pass.

## 2. Scope and Non-Authorization Flags

## 3. Problem Definition

Future executable evidence tasks must prove that every reported evidence value
is derived from a callable computation path.

Wrong problem definitions:

```text
Can a schema-complete artifact package be made internally consistent?
Can hashes match values generated by the same artifact constructor?
Can tests assert that a final verdict passed?
Can a task list baselines, ablations, leakage checks, or replay checks by name?
```

Correct problem definition:

```text
Can every reported result, baseline score, ablation score, contrast result,
leakage result, replay result, candidate score, and aggregate verdict be traced
to callable computation that consumed the declared frozen inputs and emitted
per-case outputs before aggregation?
```

## 4. Failure Mode Addressed

External red-team review of `POST-BRIDGE-ADMISSION-EXECUTABLE-001B` found that a
schema-complete and hash-consistent artifact package can still be invalid as
positive evidence when reported values are generated by constants or
self-consistent artifact construction instead of measured computation.

The admitted failure family includes:

```text
baseline_scores_from_constants
ablation_scores_from_static_tables
contrast_results_from_static_booleans
unconditional_leakage_clean_reports
fixed_trace_deltas
hash_only_replay
artifact_writer_later_verifies_own_values
unused_train_contexts
unused_seed_families
unused_counterfactual_pairs
unused_ablation_definitions
candidate_action_not_computed_from_deserialized_serialized_state
tests_asserting_pass_instead_of_computation_path
```

This contract exists to make those patterns blocking in future executable
evidence tasks.

## 5. Computed-Evidence Provenance Rule

For every future executable evidence task, every reported result, baseline
score, ablation score, contrast result, leakage result, replay result,
candidate score, and aggregate verdict must be derived from a callable
computation path.

Reported evidence is invalid if it is produced by:

```text
literal constants
static dictionaries
unconditional clean reports
self-reported JSON
tests that merely assert pass
hash replay without behavior recomputation
artifact construction that writes the same value it later verifies
rejection sampling that chooses counterfactuals after seeing desired behavior
unused frozen seed families
unused train contexts
unused heldout contexts
unused counterfactual pairs
unused ablation definitions
baseline names without callable baseline implementations
```

The required computation path must be inspectable from source, callable in
tests, connected to the reported artifact row, and capable of producing a
different result under a valid perturbation or failure-path control.

## 6. Required Metric Provenance Schema

Every score or verdict-bearing metric must record at minimum:

```text
metric_id
metric_name
producer_function
producer_module
code_path_hash
run_id
episode_ids
seed_ids
train_context_ids_consumed
heldout_context_ids_consumed
counterfactual_pair_ids_consumed
input_artifact_paths
input_artifact_hashes
input_row_count
output_artifact_path
output_row_ids
aggregation_rule
threshold_used
threshold_frozen_before_run
computed_not_literal
failure_path_available
```

`computed_not_literal` must be `true`. `failure_path_available` must be `true`.
If a field is not applicable, the metric row must say why; omission is not
equivalent to non-applicability.

## 7. Baseline Implementation Requirements

Every fair baseline must be an independent callable implementation.

Each baseline must:

```text
accept comparable legal inputs
run on the same frozen episode set or an explicitly justified subset
emit per-episode outputs before aggregation
record consumed input artifacts
record producer_function and code_path_hash
have at least one test proving the baseline function is invoked
have at least one failure-path or perturbation test showing the score can change
```

Forbidden baseline patterns:

```text
baseline score written directly into baseline_comparison.json
baseline listed by name only
baseline implemented as a static dictionary
oracle control treated as fair baseline evidence
trace-only replay treated as fair baseline evidence
```

Oracle controls may be upper-bound or leakage diagnostics only. Trace-only
replay may be integrity hygiene only. Neither is fair baseline evidence.

## 8. Ablation Implementation Requirements

Every required ablation must rerun episodes under a real intervention.

Each ablation must:

```text
define the intervention function
record intervention target fields
record pre-intervention state hashes
record post-intervention state hashes
rerun candidate behavior
recompute score from outputs
compare against a frozen sensitivity threshold
emit per-episode outputs
prove the intervention was actually applied
```

Forbidden ablation patterns:

```text
ablation score written directly as a literal
sensitive=true without measured degradation
ablation that only deletes evaluator-required fields rather than mechanism state
ablation report that cannot identify which episodes were rerun
```

## 9. Contrast Implementation Requirements

Contrasts such as the following must use pre-frozen contrast pairs:

```text
same_identity_different_state
different_identity_equivalent_state
memory_key_corruption
state_replacement
cross_agent_state_swap
duplicate_identity_token_contrast
future equivalent contrast families
```

Each contrast must:

```text
consume contrast pair IDs from the frozen manifest
not perform rejection sampling after observing desired behavior
rerun candidate behavior
compute delta from observed outputs
record per-pair outcomes
record producer_function and code_path_hash
```

## 10. Leakage Scanner Requirements

Leakage checks must be implemented as real scanners.

Each scanner must:

```text
define scanned input surfaces
scan candidate inputs
scan trace rows
scan serialized state
scan provenance rows
scan artifact paths
scan fixture names
scan labels
scan verifier-only fields where applicable
emit hits if present
include at least one positive-control case showing the scanner can fail
include at least one clean-control case showing it does not always fail
record scanner_function and code_path_hash
```

Forbidden leakage patterns:

```text
unconditional clean leakage reports
hits=[]
clean=true without scanning a real input surface
forbidden_source_scan_result.clean=true as a generated constant
```

## 11. Replay and Behavior-Causal Replay Requirements

Replay is not sufficient if it only verifies hashes.

Behavior-causal replay must:

```text
load serialized_state from artifact
deserialize it through the same public path used by candidate behavior
load or reconstruct observation from artifact or frozen seed
recompute candidate_action_id from serialized_state + observation
compare recomputed action to recorded action
recompute later behavior or score if claimed
emit mismatches if behavior cannot be reproduced
record replay_function and code_path_hash
```

Forbidden replay patterns:

```text
state_replay_hash written equal to post_bridge_state_hash during artifact generation
trace hash-chain replay treated as behavior-causal replay
serialized-state replay that only rehashes stored snapshots
replay without observation or observation seed available in artifacts
```

Hash-chain and artifact-integrity replay remain useful hygiene, but they cannot
be upgraded into behavior-causal replay evidence.

## 12. Frozen Input Consumption Requirements

Every frozen seed family, train context, heldout context, counterfactual pair,
cross-agent swap pair, duplicate identity-token contrast, and ablation
definition must be either:

```text
actually consumed by a computation path, with IDs recorded in provenance
removed from the freeze before execution
```

Any unused frozen item blocks the executable task with:

```text
failed_unused_frozen_input
```

Adding unused frozen inputs to make a manifest look stronger is evidence
decoration, not evidence.

## 13. Candidate Serialized-State Causal Path Requirements

If a task claims behavior depends on serialized carried state, candidate
behavior must:

```text
read state through the deserialization path
record deserializer_function and code_path_hash
use deserialized fields in candidate action computation
prove that replacing serialized_state changes behavior under frozen contrasts
prove that identity token alone does not explain behavior
```

Forbidden candidate-state patterns:

```text
computing action from in-memory pre_state while serialized_state is created later
storing serialized_state without consuming it in the behavior path
identity-token lookup treated as carried-state causality
memory-key lookup treated as carried-state causality
```

## 14. Test Requirements

Tests must verify computation paths, not just final pass verdicts.

Required tests for future executable evidence tasks:

```text
artifact schema validity
metric provenance schema validity
every reported metric has producer_function and code_path_hash
no verdict-bearing metric is generated from known static dictionaries or literals
baseline implementations are invoked
ablation intervention functions are invoked
leakage scanners can fail on positive controls
replay recomputes behavior from serialized_state + observation
frozen seeds, contexts, and pairs are consumed or explicitly absent
failure paths produce blocker verdicts
tests do not merely assert verdict == pass
```

Forbidden tests:

```text
asserting result.verdict == pass as primary evidence
asserting all leakage clean without testing scanner behavior
asserting all ablations sensitive without verifying rerun/intervention
asserting baseline_gate_passed without checking baseline calls
```

## 17. Adoption Rule for Future Executable Task Cards

Every future executable evidence task in this repository must cite:

```text
COMPUTED-EVIDENCE-PROVENANCE-CONTRACT-001A
```

Every future executable task card must include:

```text
computed-evidence provenance gate
metric provenance schema
blocker verdicts for provenance failure
tests for baseline invocation
tests for ablation rerun
tests for scanner positive controls
tests for replay behavior-causality
tests for frozen input consumption
```

Any future executable task that does not cite this contract must block before
execution unless it is explicitly scoped as legacy negative evidence
preservation.

Equivalent machine-readable policy:

```text
missing_contract_citation_policy = block before execution
```

## 18. Claim Ceiling

Maximum claim:

```text
bounded repo-standard contract evidence only
```

This contract can support only the claim that the repository now has a
forward-facing provenance standard for future executable evidence tasks. It
does not validate any old run or future run by itself.

## 19. What This Standard Cannot Prove

This standard cannot prove:

```text
bridge readiness
EGO readiness
companion readiness
mechanism validity
theory validity
agency
selfhood
consciousness
real relationship learning
real emotion
subjective experience
stable user benefit
correctness of any future executable task
```

It also cannot prove that future task authors will comply. Compliance requires
task-card adoption, executable checks, failure-path tests, and artifact review
under the claim ceiling above.
