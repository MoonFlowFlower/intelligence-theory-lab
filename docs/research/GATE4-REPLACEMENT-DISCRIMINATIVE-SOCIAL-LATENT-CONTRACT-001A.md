## Wrong Problem Definition To Avoid

Reject this framing:

> Make Gate4 pass.

Use this framing instead:

> Define a future Gate4 task where social-latent success cannot be explained
> by lookup, retrieval, table, transition, or graph-cache families.

The current 001C collapse is not a small implementation defect. The strongest
surviving explanation is shallow stream-keyed lookup over `(seed, context_id,
partner_id)`, not social latent inference.

## Replacement Gate4 Target

A future replacement Gate4 may become discriminative only if it forces
generalization and intervention-response across social latent variables rather
than allowing table lookup over fixed stream keys.

The replacement task must require future evidence of at least:

- unseen partners
- unseen contexts
- unseen preference transitions
- unseen counterfactual interventions
- active information-seeking
- intervention-response
- feedback-dependent update
- behavior change after observation
- serialized-state replay
- contrast against independent baselines

These requirements are necessary contract constraints only. They are not
sufficient for agency, selfhood, consciousness, real emotion, relationship
learning, stable autonomy, or functional subject proof.

## Observation Schema Constraints

The future task must specify that candidate and baselines receive the same
observation/action/reward/history interface.

The future task must prevent raw access to:

- seed
- context_id
- partner_id
- phase token
- split label
- oracle latent label
- artifact path
- bundle path
- any deterministic key that identifies the answer

If IDs are unavoidable, the contract must require all of:

- ID remapping
- heldout remapping
- explicit table-family baselines using those IDs
- evidence that remapped IDs cannot be joined back to raw answer keys

Candidate-only redaction is forbidden. Candidate and baselines must share the
same legal input interface.

## Split Requirements

The future task must require splits covering:

- seen partner / unseen context
- unseen partner / seen context
- unseen partner / unseen context
- unseen preference transition
- counterfactual intervention
- active query-required episodes
- heldout episodes with remapped IDs

The future contract must explicitly reject train/test leakage through stable
IDs, phase labels, deterministic ordering, fixture names, artifact names,
bundle paths, and any answer-key-bearing serialized fields.

Any split where a stream-keyed count table over train-visible fields can tie or
exceed the candidate must block the future Gate4 claim.

## Mandatory Baseline Families

The future execution contract must include independent callable baselines for:

- stream-keyed count table
- normalized retrieval
- nearest-neighbor lookup
- context-partner table
- `graph_lookup`
- `transition_table`
- `successor_map`
- `count_table`
- `fsm_planner`
- `episodic_traversal`
- no-state ablation
- no-feedback ablation
- no-action ablation
- oracle-label positive control only

Each baseline must be callable and independently implemented. No baseline may
be represented only by static JSON, hardcoded scores, static dictionaries,
self-reported pass/fail labels, or tests that assert a pass verdict.

Baselines must be run under the same legal input interface as the candidate.
Any hidden candidate-only information, baseline-only handicap, or post-hoc
baseline omission blocks the future contract.

## Computed Evidence Provenance Contract

The future execution contract must require all reported metrics to be computed
by callable paths.

Every reported score must record:

- `producer_function`
- `input_artifacts`
- `run_id`
- `seed_ids`
- `context_ids`
- `partner_ids`
- `episode_ids`
- `split_id`
- `aggregation_rule`
- `code_path_hash`
- `baseline_invocation_path`
- `ablation_invocation_path`
- `leakage_scanner_path`
- `replay_recompute_path`

Hardcoded scores, unconditional clean reports, static dictionaries,
renderer-visible behavior as causal evidence, and tests that merely assert pass
are forbidden.

Baseline scores, ablation effects, leakage results, replay metrics, contrast
metrics, and final verdicts must all be derived from callable computation
paths. If any required producer path is missing, unused, uncalled, or only
represented by literal JSON, the future verdict must block.

## Ablation Requirements

Future ablations must rerun episodes under real interventions, including at
minimum:

- no-state
- no-feedback
- no-action
- no-partner-history
- no-active-query
- shuffled-feedback
- counterfactual-partner-transition

Ablations must not be post-hoc score edits.

Each ablation must record the intervention function, affected fields, episode
set, run id, aggregation rule, code path hash, and whether the expected causal
dependency changed. If an ablation name does not match the intervention, the
future task must block instead of renaming the failure into a pass.

## Leakage Requirements

Future leakage scanners must include:

- real-bundle scan
- positive-control leakage case
- ID leakage scan
- phase-token scan
- bundle-path scan
- oracle-label scan
- answer-key scan
- deterministic-order scan

A scanner that cannot fail on a positive control must block.

Synthetic controls may be used only as additional controls. They must not
substitute for a real-bundle scan. Excluded paths must be recorded as
`not_scanned`, never `clean`.

## Replay Requirements

Future replay must recompute candidate behavior from:

- `serialized_state`
- observation
- action policy path
- update path
- feedback history

Replay must not merely compare stored action hashes.

Replay must verify both action recomputation and state-update recomputation.
Hash-only replay, stored-action replay, or replay that only proves artifact
stability is insufficient for replacement Gate4.
