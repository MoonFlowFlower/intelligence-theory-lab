## Measurement Object

`ACSB-CONTINGENCY-BOUNDARY-UPDATE-OBJECT-001A` measures whether a future
candidate updates an internal self/external boundary state from
action-conditioned contingency evidence and uses that updated boundary state in
a non-identical future probe.

The measured object is a composite future result with three fields:

1. `boundary_assignment_update`: a candidate-produced update over legal channel
   identifiers, containing controllable versus external confidence and
   uncertainty after action, no-action, external-transition, decoy, and
   intervention observations.
2. `probe_behavior`: a future action choice, withholding choice, or output under
   a heldout probe context where the correct behavior depends on the updated
   boundary state and not on the last row alone.
3. `probe_boundary_explanation_token`: a compact output token naming whether the
   probe effect should be treated as self-caused, external-only, decoy, or
   unresolved. This token is not a natural-language explanation and must be
   derived from the same legal candidate behavior path.

The future runner must compute evaluator targets from hidden environment
generation state that is never present in candidate, baseline, ablation, replay,
or leakage-scanner legal inputs.

## Episode Structure For Future Execution

### Phase 1: Prior Boundary State

The candidate starts from serialized bounded state with uncertainty over which
channels are controllable by its own actions and which channels are external or
decoy. The state may contain prior legal evidence, uncertainty, history needed
for replay, state version, hashes, and episode/context identifiers. The state
must not contain target labels, oracle labels, legal answer fields, correct
actions, self/external answer flags, future probe answers, precomputed verdicts,
cached scores, or report-only pass/fail fields.

### Phase 2: Action-Effect Evidence

The candidate receives observations after its own actions, after no-action
intervals, and after externally caused transitions. The key signal is
action-conditioned contingency:

- what changes after the candidate acts;
- what changes without candidate action;
- what changes after external perturbation;
- what changes under decoy contexts;
- what persists into heldout probe contexts.

### Phase 3: Intervention

The environment changes the action-effect boundary structure or separates
self-caused and external-only channels. The intervention must be strong enough
that a stale transition table, cached graph path, or memorized episode row can
fail unless it updates from new legal evidence.

### Phase 4: Heldout Future Probe

The candidate receives a non-identical probe context. It must produce
`boundary_assignment_update`, `probe_behavior`, and
`probe_boundary_explanation_token` from serialized state plus current
observation. The probe must not be row-identical to evidence contexts, and
superficial context features must be insufficient for lookup.

- previous action taken by the system;
- observed effect after action;
- observed effect after no-action or external event;
- local context features;

Forbidden observation fields:

- answer-bearing aliases;
- post-hoc evaluator labels;
- future outcome;
- precomputed candidate score;
- clean/dirty verdict;
- validator verdict;
- manifest completeness field.

## Required Intervention Definition

The future intervention must be a real change to action-effect boundary
structure, not a report mutation or label flip. Acceptable intervention types:

- swap an action-effect mapping for a controllable channel while preserving
  superficial context;
- introduce external-only effect changes that mimic self-caused effects;
- remove action control while preserving similar marginal effect statistics;
- add decoy effects correlated with context but not with action;
- create counterfactual no-action observations;
- test delayed future behavior after distractor contexts.

The intervention must be able to make a stale candidate fail. It must not be
equivalent to flipping a target label in a manifest.

## Required Measured Output

The future task must compute the composite object from:

- serialized state;
- current observation;
- candidate behavior path;
- independent baseline paths;
- ablation paths;
- evaluator-hidden generation state used only for scoring.

The measured output must not be requirement presence, scope lock, manifest
completeness, validator cleanliness, field presence, report shape, JSON parse
success, forbidden-claim scan cleanliness, source artifact existence, or replay
hash equality.

## Required Independent Callable Baselines

The future executable task must include independent callable baselines:

1. `transition_table_baseline`: uses legal observable state/action/effect rows
   without hidden labels or target fields.
2. `fsm_baseline`: uses finite-state transition rules over observations to test
   whether a compact hand-coded state machine solves the surface.
3. `graph_cache_or_episodic_traversal_baseline`: uses seen
   context/action/effect graph traversal or nearest episodic retrieval.
4. `action_effect_frequency_without_boundary_state_baseline`: tracks
   action-effect frequencies but has no explicit self-boundary update.
5. `recency_or_last_effect_baseline`: uses the most recent effect or
   intervention.
6. `majority_random_control_baselines`: provide minimal sanity baselines.
7. `oracle_leakage_positive_control`: intentionally receives answer-bearing
   fields and must score high if scanner and task wiring are real.

The strongest expected baseline is:

`transition_table / FSM / graph-cache / episodic traversal over legal state, action, and effect observations, plus action-effect frequency without self-boundary state`.

If these baselines match or beat the candidate under heldout interventions, the
future surface is downgraded or closed rather than patched into a pass.

## Required Mechanism-Removing Ablations

The future task must rerun under real interventions with these ablations:

1. `freeze_boundary_update`: candidate receives prior state but cannot update
   self-boundary state after new evidence.
2. `remove_action_conditioned_contingency`: candidate sees effects but not
   action-effect linkage.
3. `remove_no_action_counterfactual`: candidate cannot compare action-caused
   and no-action/external changes.
4. `shuffle_action_effect_linkage`: preserves marginal action/effect
   frequencies while breaking actual contingency.
5. `replace_boundary_state_with_recency_state`: uses recent observations only,
   without explicit self-boundary representation.
6. `reset_state_before_probe`: removes persistence of boundary update before
   future behavior is measured.

Ablation success must be impossible if the future runner only reads stored
scores or report fields.

## Required Leakage Positive Controls

The future task must include leakage scans with positive controls:

1. explicit target action/output field;
2. oracle boundary label;
3. benign answer alias;
4. hidden ID that maps one-to-one to answer;
5. future outcome in observation/state;
6. stored verdict/score field.

The scanner must fail these positive controls. A scanner that only reports clean
on the normal artifact is insufficient.

## Required Replay Definition

Replay must recompute future behavior from:

- serialized state;
- observation;
- intervention description;
- candidate behavior path;
- baseline behavior path;
- ablation behavior path.

Replay must not compare stored hashes only, compare stored reports only, reuse
stored verdicts, replay validator decisions, replay manifest field
completeness, or replay target labels.

Replay must show that mechanism-relevant changes to serialized state or
observation change recomputed behavior. If changing the state or observation
does not affect recomputed behavior where it should, the future surface blocks.

## Required Graph-Cache / Lookup / FSM Challenge

The future surface must make lookup-style baselines meaningful and potentially
strong. It must require a split where:

- train/evidence contexts do not trivially enumerate heldout probe contexts;
- superficial context features are insufficient;
- action-effect contingencies can change under intervention;
- no partner/context/ID maps directly to the answer;
- row-level memorization is insufficient;
- transition-table, FSM, graph-cache, and episodic traversal baselines are
  independently run and reported;
- candidate-level performance by those baselines downgrades or closes the
  surface.
