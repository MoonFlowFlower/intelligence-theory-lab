## Selection Rationale

`action_conditioned_self_boundary` is selected because it can put action-conditioned contingency, self/external boundary update, future behavior, mechanism-removing ablation, and cheap-baseline pressure into one measurement object. That makes the surface more fail-able and more aligned with bounded functional-subject proxy evidence than a generic intervention-response update surface.

This is not a positive result for the existing action-conditioned preflight. The existing `ACTION-CONDITIONED-SELF-BOUNDARY-PREFLIGHT-001A` artifact is blocked as invalid-harness negative evidence and must not be reused. The selected class only remains viable as a new specification if it explicitly prevents the prior failure modes: oracle-target tautology, semantic answer-bearing legal fields, omitted fair simple baselines, same-state proxy leakage, benign answer aliases, and replay tautology.

`intervention_response_update_persistence` is deferred because it is behavior-bearing but more likely to collapse into generic adaptation, recency, or fixed flip-after-intervention. It should become the fallback only if the selected self-boundary object cannot be specified without oracle/lookup/FSM collapse.

## Selected Surface Specification

- `selected_surface_name`: `action_conditioned_self_boundary`
- `state`: serialized bounded self-boundary state containing prior action-effect contingency evidence, controllable-channel vs external-channel belief distribution, uncertainty, prior boundary state, intervention ledger, and delayed-use markers. The state must not contain answer-bearing labels, future outcomes, action-index target aliases, context IDs as target keys, oracle fields, or benign named answer aliases.
- `observation`: current environment observation plus allowed prior action/effect observations. Legal observation fields must be sufficient for a nontrivial legal reference to exceed random/majority while still denying direct target labels, future outcome fields, hidden rule labels, row IDs, context IDs, and answer-bearing action names.
- `intervention`: perturb action-to-effect contingency or self/external channel structure while holding superficial context features insufficient for lookup. Include counterfactual no-action or externally-caused effects, decoy effects, and heldout action/effect structures.
- `measured_future_behavior_or_state_update_or_output`: future action selection or output conditioned on updated action-effect boundary evidence; boundary-state update after intervention; downstream behavior that distinguishes self-caused effects from external-only or decoy effects.
- `independent_callable_baseline`: independently implemented lookup table, transition table, FSM planner, graph-cache, episodic traversal, action-effect frequency model without self-boundary state, recency/win-stay-lose-shift heuristic, majority/random controls, and oracle-leakage positive control.
- `real_mechanism_removing_ablation`: freeze self-boundary update; remove action-conditioned contingency update; randomize action/effect linkage; remove counterfactual no-action comparison; collapse self/external channel distinction.
- `leakage_positive_control`: inject future outcome fields, self/external oracle labels, action-index target aliases, context IDs as target keys, benign named answer aliases, or direct action-effect answer encodings, and require the leakage scanner to detect each injected path.
- `replay_from_serialized_state_plus_observation`: recompute boundary-state update and future behavior from serialized self-boundary state plus current observation through the same callable path used by the candidate-facing measurement. Stored hashes, stored verdicts, stored reports, and evaluator-only target functions are not replay.
- `graph_cache_lookup_transition_table_fsm_episodic_traversal_challenge`: mandatory. These challengers must receive the same legal inputs and be considered decisive blockers if they match or beat the candidate under heldout interventions.
- `block_or_close_condition`: close or block if the object measures requirement presence, scope locks, manifest completeness, validator cleanliness, field presence, or report shape; if legal fields deterministically encode the target; if no independent cheap baseline can be specified; if no mechanism-removing ablation can be specified; if replay cannot recompute from serialized state plus observation; if leakage positive controls cannot be defined; if lookup/FSM/transition-table/graph-cache/episodic traversal challenge is not meaningful; or if implementation is required before the measurement object is clear.
- `strongest_baseline`: transition table / FSM / graph-cache / episodic traversal over legal state, action, and effect observations, backed by action-effect frequency without self-boundary state.
- `strongest_objection`: prior action-conditioned self-boundary work already failed as an invalid harness because a legal interface encoded the target, fair simple baselines were omitted, and replay became tautological. A weak new specification would repeat that failure rather than create a discriminative behavior-bearing surface.
- `why_the_rejected_surface_loses_or_is_deferred`: `intervention_response_update_persistence` is deferred because it can be behavior-bearing but is more easily explained by recency, last observation, or fixed flip-after-intervention. It is a fallback surface only if the selected self-boundary specification cannot block oracle/lookup/FSM collapse.
