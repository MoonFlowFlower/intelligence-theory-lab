## 3. Governance adoptions

### G1. Control-battery extension (contract-revision proposal, dormant until post-S6)

Three controls, mandatory for any P1+ card whose candidate claims structural / categorical / typed priors:

- `format_matched` — same I/O format and schema scaffolding as candidate, mechanism removed.
- `schema_shuffled` — slot names/bindings permuted at fit time.
- `wrong_prior` — deliberately mis-specified slot structure at matched capacity.

Rationale: the current battery (graph-cache family, obs-decoders, LS, RAG/NN, sequence models) does not cover the failure mode "structure wins only as formatting". Equivalence verdicts against these controls must carry power/MDE analysis (discovery-loop lesson: small-data separation evaporates).

### G2. Failure-taxonomy additions (dormant, same activation)

- `CATEGORY_TRUTH_COUPLING` — generator/evaluator/candidate share the category ontology; instrument invalid. Generalizes LRGG `invalid_oracle_baseline_coupling` (`artifacts/LRGG-CANDIDATE-FREE-TIER0-2`).
- `WRONG_PRIOR_MATCHES` — wrong-prior control matches candidate; prior-structure claim blocked.
- `CATEGORY_FORMAT_ONLY` — format-matched control matches candidate; formatting benefit only.
- `CATEGORY_ABLATION_NO_EFFECT` — removing a category slot does not damage its pre-registered cell; no mechanism claim for that slot.

### G3. Evidence type system (design-only registration)

`type(O) -> {allowed updates, allowed actions, allowed claim level}` — one enforceable schema unifying claim ceiling, provenance, and modality (Fact != Claim, Observation != Intervention, Possible != Actual, Memory != Evidence, Correlation != Cause, Past != Future). This is the machine-checkable form of discipline this lab already enforces manually, and the natural extension of the C0-C3 ladder. Registered for Route-1-style external memory governance and for lab-report linting. No runtime, no evidence.

### G4. Loop-edge declaration predicate (card-template addition, dormant)

Every future candidate card must declare: (a) which loop edge(s) — categorize / believe / predict / select / update / consolidate — the candidate claims to improve, and (b) the pre-registered cell where cutting that edge must hurt. Cards that cannot answer are deprioritized. This is the only surviving content of the source's "ouroboros compression".

### G5. Anti-hardcoding audit refinement

The audit question "is it if-else disguised as mechanism" gains a constructive trichotomy: (A) hardcoded answers — forbidden; (B) hardcoded question-form with learned content — admissible as inductive bias, must face the G1 controls; (C) soft/ablatable priors — admissible. Auditors classify structure as A/B/C instead of binary.

## 4. Mandatory firewall: category-vocabulary / environment coupling

If CPL vocabulary (slot names, category ontology, typed schema) is used in designing an environment family or its evaluator, then:

1. any CPL-class candidate result on that family is automatically capped at "in-ontology evidence";
2. promotion requires replication on a cross-ontology environment (independent generator vocabulary, surface-remap, camouflage on/off controls);
3. generator/evaluator/candidate ontology overlap must be declared in the card; undeclared overlap discovered post-hoc = `CATEGORY_TRUTH_COUPLING`, instrument invalid.

Rationale: the source report proposes using the category ontology as "environment design vocabulary" in P0/N0 while later testing category-prior candidates — the exact self-licensing loop that produced the LRGG oracle-coupling invalidation and the Gate4 cross-family-social tautology.
